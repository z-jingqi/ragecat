# 25 类精确移植的验收工作流

这里的「角色」是验收岗位，不是游戏角色。流程定义不会自动启动代理、安装插件或宣布特效已通过。
本文件是可复用验收标准，不记录某次运行结果。运行日志、图像、视频和逐项验收记录保存在仓库外。

## 验收对象

本轮对象是 Sprite Fusion 的 25 个代码特效家族、41 个已列出的 situation，单独使用
`spritefusion_exact/` 命名空间，Godot 工程为 `spritefusion_exact/godot/`。
目标实现按 `scripts/core/` 和 `scripts/effects/{slug}.gd` 分离，实际映射以实现交付的清单为准。
旧的 `effects/pixel/` 和 `preview/godot/` 是独立资产，不因视觉类似而代替本轮原算法移植。
流程文件并不证明这些实现路径已经存在或验收完成。

清单来源是 2026-11-03 获取的 [Sprite Fusion 特效目录](https://www.spritefusion.com/pixel-art-vfx)。
源文件、原始默认值及其 SHA-256 在每批验收前固定；如果上游变化，先报告差异，不能静默换源。
家族数不是场景数，也不是已通过的测试数。每个 situation 必须单独有证据。

## 七个岗位

从 [pstack-acceptance](../.agents/skills/pstack-acceptance/SKILL.md) 进入完整岗位说明。

1. **来源与许可验收**：固定源字节、散列、来源、许可、25/41 覆盖与目标文件映射。
2. **算法一致性验收**：逐状态核对随机序列、取整、时序、更新次序、双缓冲和全部 hooks。
3. **原生画面验收**：相同输入的像素差异、Godot 实际渲染、原速动画和参数交互。
4. **宿主接入验收**：真实调用、坐标、纹理、参数入口；单独报告游戏接入及玩法不变性。
5. **生命周期验收**：首用、重播、叠加、暂停、取消、退出、重入及资源释放。
6. **性能验收**：事先固定负载与预算，实测冷启动、稳态和资源增长，不靠降低一致性过关。
7. **总验收负责人**：核验证据、处理争议、复验修复并给出逐项结论；不以投票替代事实。

角色可以按容量分批执行。若同一执行者兼任多个岗位，明确写为多轮自审；不能声称独立评审或多模型评审。
实现者不代替独立验收者签署自己的最终独立结论。无独立人员时可以交付自检结果，但说明独立验收尚未完成。

## 执行顺序与门槛

1. **固定范围**：记录精确源散列、目标提交、全部 situations、实现文件、默认参数、宿主与原始参考。
   先确定许可；预览图、美术、代码分别审查，不能由一个代码许可证推断其他资源可再分发。
2. **固定可复现场景**：给出随机种子/随机数流、事件、帧或模拟时刻、delta 序列、相机、像素尺寸、
   背景、Godot 版本和 renderer。匹配源程序的真实语义，不用新参数调出近似外观代替移植。
3. **算法门槛**：每个 situation 与源参考做数值/状态差分，覆盖默认、边界、结束和 hooks。
   只看源散列、通过导入或调用成功均不满足算法验收。必要时证明比较器会拒绝错误输出。
4. **画面门槛**：比较真实像素输出并在原生 Godot 渲染，保存配对帧、差分与正常速度录制。
   逐像素一致的无条件声明需要差异像素为零；非零容差及其原因必须单列，不能仍宣称完全像素一致。
   JS/Godot 浮点或栅格差异必须解释和记录，不能删除失败帧、裁掉失败区域或更换参考。
5. **接入与生命周期门槛**：检查真实预览 API、全部参数和场景切换，完成岗位定义的中断/清理用例。
   游戏适配单独验收；未接入游戏的效果只可通过独立预览，不虚构游戏触发条件或玩法验证。
6. **性能门槛**：先明确可比较场景、指标和数字预算，再实测。没有预算或测量则分别报告待定/未运行，
   不能把「不卡」当结论，也不能裁减源算法来达标。
7. **复验与交付**：实际检查各岗位提供的文件/结果，逐情况填写 verdict。修复后在新提交复验相关门槛。
   唯一集成人员在已有授权内串行发布并核验远端提交；流程本身不授权推送、合并、部署或新依赖安装。

**强制区分**：实现存在、算法一致、原生画面一致、预览接入、游戏接入、用户视觉确认是不同结果。
缺项必须是 `fail`、`blocked` 或 `not_run`；`not_applicable` 仅用于范围明确不包含的项目，并写清理由。
全部 41 个 situation 的强制门槛通过，才可以称 25 类精确移植验收通过。

## 交接与证据格式

每个岗位收到相同的用户意图、源快照、目标提交、范围、可执行入口和下面的证据字段。
评审只读实现，允许在仓库外产生一次性检查输出；发现问题交还原实现者，不边验收边偷偷改实现。
新工具、外部执行和发布继续遵守宿主权限。不要为了运行上游检查器而安装完整 pstack。

每条记录包括：
- 家族 ID、situation、岗位、评审者/执行者、是否独立。
- 源 URL/文件/SHA-256、目标 commit/文件、实际命令与退出状态。
- seed、参数、事件/时刻、viewport/scale、engine/renderer、机器与负载（相关时）。
- 预期、实际、差分指标/阈值、截图或视频、日志位置；所有 artifact 明确对应当前目标。
- `pass` / `fail` / `blocked` / `not_run` / `not_applicable`，理由及未覆盖边界。
- 发现问题的严重度、文件/符号、可重现步骤、修复负责人和复验结果。

无法运行时写出准确阻塞项，不填写假命令或假结果。只有 headless 的记录不能填写「画面通过」。
用户视觉确认单列来源，不可由代理代签；接入配置的主动改良不能被混为原始默认效果。
