# 山海经像素 Roguelike 代码优先 VFX 制作任务书 V2.0

## 一 当前方向与版本关系

**特效以代码驱动的实时几何、粒子、轨迹和 Shader 为主，不用预制精灵图集或逐帧 PNG 动画制作。所有效果都要干净利落。** 原清单 22 类的动态行为都能用代码实现；需要区分的是独立程序生成、可选静态造型，以及依赖角色/怪物已有外观的反馈。

本版是后续制作依据，取代 [V1.0 原文](shanhaijing-pixel-roguelike-vfx-brief-v1.0.md) 中的默认生产管线、交付格式、帧数帧率和预览要求。V1.0 仅作历史归档，原文不改写。保留原有 22 个 ID 与第一阶段 10 项优先序；按最新要求，获准范围内的多个特效可以并行，完成自检即可提交保存，再逐项展示和验证，有问题继续修正，不再等待上一项确认才开工。

本版修订本身不代表已实现任何特效、已修改预览器或已通过 Unity 验收；不恢复旧特效。制作在已批准范围内推进，各项独立验证。

| 项目 | 要求 |
|---|---|
| 游戏 | 2D 俯视角 Roguelike，玩法参考 Brotato，题材为《山海经》 |
| 视觉 | 精致 16-bit 像素风；清晰轮廓、有限色阶、统一像素密度，干净利落 |
| 正式目标 | Unity 2D URP；制作前记录实际 Unity、URP 版本和 Renderer 配置 |
| 主生产手段 | Unity C#、程序化 Mesh、Particle System、LineRenderer / TrailRenderer、URP Shader |
| Godot | 仅验证视觉、时间变化和参数响应，不代替 Unity 正式验收 |
| 辅助美术 | 必要时用单张静态纹理、轮廓或网格；不将动画烘焙为图集 |
| 核心交付 | 源码、参数预设、使用说明、真实运行预览和分项验证状态 |

## 二 哪些能用代码 哪些需要视觉输入

### 三种实现方式

- **A 独立程序化**：弧带、环、折线、扇形、碎片、噪声、粒子和运动曲线可直接生成，无外部美术也能制作可用版本。运行时生成网格/纹理仍属于程序化。
- **B 程序化为主 加可选静态辅助**：动态由代码负责；准确表达武器造型、古纹、兽形、特定岩块时，可加单张纹理或网格。纯代码也可能画出来，只是成本和美术可控性不同，不能说“代码做不了”。
- **C 宿主依赖程序化**：贴体闪色、残影、沿身体溶解等，需要宿主的 Sprite / Mesh、alpha、当前姿态或渲染结果。这不是另画一套特效帧；宿主外观是运行时输入。宿主若是程序化形状，也可读取该形状。

分类可以组合使用。**代码能控制动画，不等于无须任何视觉输入。** 通用算法不能在缺少设计定义时自动忠实复现指定神兽、角色姿态、武器花纹或手绘构图；这些需要明确设计数据或美术输入。真实角色贴体效果也不能只用通用圆形占位物证明完成。

“不用精灵图”指不用 Sprite Sheet / Flipbook 制作特效动画，不禁止读取游戏已有角色 Sprite，也不禁止有必要的单张静态素材。新增素材依赖必须说明用途、替代方案和授权，不能把可选项变成全库前置条件。

## 三 22 类特效实现矩阵

以下是基于需求的工程建议，不是引擎自动提供的成品效果。**P0** 是原第一阶段；**P1** 是后续待排期。火焰与雷电的 P0 仅覆盖首发子类型。Godot 列描述最小预览适配，Unity 列要求在正式目标中另行检查。

| ID 与特效 | 优先级 | 类型与素材依赖 | 推荐 Unity 实现 | 最小 Godot 预览 | Unity 验收重点 |
|---|---|---|---|---|---|
| VFX-01 武器挥砍 | P0 | A；特殊刀纹可选 B | C# 弧带 Mesh，控制扫角、宽度、亮芯和消退 | 自绘弧带 / Polygon2D | 锚点、方向、范围、时序一致；不是静态弧线缩放 |
| VFX-02 武器拖尾 | P0 | A，输入武器轨迹；原貌残影才依赖外观 | 采样武器端点生成带状 Mesh；简单情况用 TrailRenderer | 轨迹队列 + Line2D / 自绘带 | 留下真实历史轨迹，停止后消退；瞬移不拉长线 |
| VFX-03 远程弹道 | P0 | A / B；法球可无素材，特定飞刀/箭矢可用静态造型 | C# 运动 + 几何弹体 + 粒子/尾迹 | 参数化弹体与实时轨迹 | 方向、速度、转向、命中位置正确；伤害由游戏层判定 |
| VFX-04 攻击命中 | P0 | A；不要求怪物贴图 | 定向碎片粒子、短线、冲击环 | 自绘碎片 / CPUParticles2D | 从真实接触点爆发，响应入射方向，干脆结束 |
| VFX-05 主角受击 | P0 | C；宿主外观、alpha 与材质状态 | C# 驱动宿主 URP Shader 的局部亮度/闪色 | 测试宿主 + CanvasItem Shader | 只作用于该角色不透明区域，保留边缘并恢复原状态，不默认全屏闪白 |
| VFX-06 闪避残影 | P1 | C；当前外观、姿态、变换 | 采样宿主，池化历史姿态，逐个退色 | 保存宿主外观与历史变换 | 残影留在历史世界位置；翻转、枢轴和动画切换正确 |
| VFX-07 火焰 | P0 首做爆炸 | A / B；静态火苗/噪声可选 | Particle System + 程序色块/Shader；火球、爆炸、燃烧分别定义 | 粒子或自绘火团 + 时间包络 | 爆炸有膨胀与余烬，持续火焰有流动，不只是同一图缩放 |
| VFX-08 雷电 | P0 首做雷击 | A；闪电链需实时目标列表 | 固定种子的分段折线/分叉 + Mesh / LineRenderer + 短脉冲 | Line2D / 自绘折线 | 起终点匹配目标；有节奏更新，不每帧无约束随机闪烁 |
| VFX-09 冰霜 | P1 | A / B；贴体冻结为 C | 多边形冰锥、碎晶粒子；冰冻层用宿主 Shader | 自绘晶体；贴体用宿主测试图 | 冰锥、冻结、碎裂区分；贴体层服从宿主轮廓 |
| VFX-10 毒雾 | P1 | A / B 为世界区域；附体中毒为 C | 区域粒子/噪声 Shader；宿主染色单独实现 | 区域粒子；附体用宿主 Shader | 毒区位置、范围清楚；附体效果随宿主并受 alpha 约束 |
| VFX-11 旋风 | P1 | A；特殊风纹可选 B | 螺旋轨迹、层叠弧带、旋转粒子 | 自绘螺旋和轨迹 | 旋向与半径可读，不擅自实现战斗吸附判定 |
| VFX-12 震地 | P1 | A / B；指定岩块可选静态形状 | 分叉裂纹、扩张环、石块 Mesh/粒子 | 自绘裂纹和抛落碎块 | 地面传播与碎块层次分开，不能只用圆环代替全部效果 |
| VFX-13 怪物出生 | P0 | A / B；本体渐显为 C，特定召唤纹样可选 | 召唤环、聚拢粒子；渐显时绑定宿主 Shader | 自绘召唤环；按需测试宿主 | 出生锚点与显现时刻对齐；取消后正确清理 |
| VFX-14 怪物受击 | P1 | A 的命中粒子 + C 的本体反馈 | 复用 VFX-04，按需叠加宿主闪色/轮廓 | 命中粒子 + 宿主测试图 | 命中点与宿主响应独立；多怪物受击不串色 |
| VFX-15 怪物死亡 | P0 | A 为独立爆散；C 为沿本体消散 | 宿主 alpha/噪声阈值溶解 + 碎屑；独立爆炸另做 | 测试宿主溶解 + 少量碎屑 | 身体实际逐步消失；未绑定外观不能称为本体溶解完成 |
| VFX-16 精英怪强化 | P1 | A / B；贴体强化为 C | 光环、上升粒子、脉冲；特定图腾可选 | 环、粒子与可选宿主 Shader | 跟随目标、脚底稳定，强化状态可区分 |
| VFX-17 Boss 警告 | P1 | A；专属符号可选 B | 圆/环/扇形/矩形 Mesh，显示范围和进度 | 自绘区域与计时 | 范围、朝向、时刻匹配游戏判定数据；危险信息不只靠颜色 |
| VFX-18 异常状态 | P1 | 外附粒子为 A，贴体染色/冻结为 C | 宿主状态 Shader + 附着点粒子；燃烧、中毒、冰冻、感电各有行为 | 宿主 Shader + 附着粒子 | 状态组合、刷新、移除、死亡清理正确，不破坏原材质 |
| VFX-19 暴击 | P1 | A；不依赖角色贴图 | 定向星芒/碎片/冲击环，强化命中形状与时序 | 自绘冲击和短亮芯 | 比普通命中明确但不堆杂物、不默认整屏闪光 |
| VFX-20 护盾与治疗 | P1 | A / B；精确贴体层为 C | 环/弧/罩体投影 Shader + 治疗上升粒子 | 自绘护盾与治疗粒子 | 生成、维持、破裂分开；治疗与伤害易分辨，锚点正确 |
| VFX-21 经验拾取 | P0 | A；球体造型可选 B；实时目标变换必需 | C# 掉落/停留/吸附/抵达状态 + 程序球体与尾迹 | 同一状态规格的实时追踪轨迹 | 吸附追踪移动目标；目标失效、抵达与回收无重复事件 |
| VFX-22 升级觉醒 | P1 | A / B；指定神兽/符纹需要设计输入 | 分阶段环、径向粒子、能量柱投影，可选静态图腾 | 分层自绘几何与粒子 | 蓄能、爆发、收束有层次，不是换色放大其他爆炸 |

**22 行是家族，不是只有 22 段动画。** 火球/爆炸/持续燃烧、单点雷击/闪电链、护盾生成/维持/破裂/治疗等，各自有范围和验收。每次开工先写明子类型，不默认一次覆盖整个家族。

### 宿主效果的关键边界

- VFX-05、VFX-06 必须验证宿主 alpha、当前帧/姿态、翻转、枢轴及排序。残影保存当时外观与变换，不能只复制不变图案。
- VFX-10 的世界毒雾可以独立生成；角色中毒变色、沿体冒烟必须接宿主，两层分别验收。
- VFX-15 的独立爆炸无需本体；沿身体消散必须读轮廓。精确“原图逐像素碎散”还需额外采样设计，不能用通用灰烬冒充。
- VFX-18 的外附粒子与贴体 Shader 分开组织。贴体效果须与宿主原有材质功能协作，不能直接替换后丢失其他状态。
- 指定神兽剪影、复杂古纹不是代码绝对做不了，但要先有设计输入。缺少正式宿主时可交机制样例，贴体正式验收保留未完成状态。

## 四 干净利落的视觉标准

1. **主体先读懂**：一个明确主轮廓和动作方向，亮芯、边缘、附属粒子服务于主体；不要靠大量装饰线、碎点和彩带掩盖动作。
2. **动作果断**：攻击出现清楚、主峰明确、收束干脆；不无故重复扩散波、长时间漂浮碎屑或拖着尾巴等待消失。持续效果有一致的内部流动和干净退出，不等于一律缩短时长。
3. **服从玩法时序**：Boss 预警、蓄力、持续区域必须匹配判定时间；“利落”不能变成删掉必要预警或提前结束。避免迟缓的是无意义视觉拖延，而非玩法要求的准备时间。
4. **先看原速与实际大小**：以 1× 播放速度、实际游戏像素尺寸验证清晰度和力度；慢放、放大只用于诊断，不作为唯一展示。
5. 元素靠形状与运动区分，不是统一换色：火上升膨胀、雷折线短脉冲、冰尖锐生长碎裂、毒缓慢翻涌沉积、风环绕螺旋、土裂纹传播重块抛落。
6. 保留原元素技能分组，但不把火、雷、冰、毒、风、土硬解释为传统五行对应；五行玩法映射由游戏设计另定。

### 像素化与时间分开控制

- 统一逻辑像素尺度及世界单位换算，按角色比例确认大小，不再强制 64 / 128 / 256 动画画布。
- 优先低分辨率渲染后用 Nearest / Point 和整数倍缩放。仅关闭纹理过滤不会自动把 Mesh/线条变成统一像素风；几何和粒子也要经过一致的像素栅格。
- 如需对齐，只量化显示位置/采样坐标，保留逻辑位置、速度与追踪连续性。镜头移动、旋转、缩放时检查断线、像素跳动和闪烁；Unity Sprite 像素对齐不自动涵盖所有 Mesh/粒子。[Unity 像素相机说明](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/2d-pixelperfect-ref.html)
- 清晰色块、有限色阶，避免模糊边缘和依赖大范围 Bloom；亮芯、局部余辉仍要保留轮廓。透明区不烘焙背景，检查深灰、黑、白和地面背景上的 alpha / additive 合成。
- 计时用秒，运动用速度/加速度，不按“每帧几像素”写死。渲染帧率、模拟步长、风格化形变更新是独立参数；**取消统一 8～12 FPS、6～12 帧、12～24 帧要求**。可对特定形变采用阶梯节奏，但不降低全局运动、吸附和碰撞更新频率。
- 单次效果有起始、主动作、衰减；循环效果有进入、维持、退出。固定种子噪声按时间演化，不每帧重抽全部形状，以闪烁代替运动。
- 受击、暴击、雷击的亮度脉冲默认局部、强度与频次可控，不强制整帧纯白，不以高频闪光制造虚假力度。

## 五 Unity 正式实现与 Godot 最小预览

### 生产路线

按单项选择最小组合：C# 控制状态与计时，Mesh/粒子/线条表达形态，URP Shader 负责色阶、遮罩、溶解与贴体变化。可以配置引擎组件，不要求每个粒子都写成独立对象；Particle System 不等于图集动画。[Unity ParticleSystem API](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/ParticleSystem.html)、[Trail Renderer 文档](https://docs.unity3d.com/6000.0/Documentation/Manual/class-TrailRenderer.html)

正式 Shader 使用目标 URP 支持的 `.shader` / `.hlsl` 或可审阅的 Shader Graph。宿主 Sprite 与独立 Mesh/粒子的材质分别验证，不默认一个 Shader 适用于所有对象。[URP Sprite Unlit Shader Graph](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/prebuilt-shader-graphs-urp-sprite-unlit.html) 提供颜色、alpha、裁剪和混合基础，具体效果仍需实现。

Blender、Pixelorama 仅在确需静态辅助素材时使用，不是所有效果必经步骤。VFX Graph、第三方 Tween、完整双引擎框架都不是默认依赖。

### 最小工作流

1. 写清当前子类型、宿主依赖、参数与验收目标。
2. 若需先预览，在 Godot 为该项写最小可运行原型，用 GDScript、自绘、Line2D、CPUParticles2D 或 CanvasItem Shader 验证真实运动与调参。[Godot 自绘](https://docs.godotengine.org/en/4.6/tutorials/2d/custom_drawing_in_2d.html)、[CanvasItem Shader](https://docs.godotengine.org/en/4.6/tutorials/shaders/shader_reference/canvas_item_shader.html)
3. 展示原速真实运行录制，并为同项做 Unity 适配和正式验收；视觉评审与引擎验证分开记录，不以等待评审阻塞已获准工作。若可直接在 Unity 工作，优先正式实现，Godot 仅保留必要演示，不重复维护完整系统。
4. 若暂不能运行 Unity，可以交原型、算法/参数规格、Unity 对应实现或待实现清单；分别注明“Unity 未实现”“已写但未编译”“已编译未运行”“已运行验证”。映射说明不能当成可用组件，Godot 通过不能当成 Unity 通过。
5. 单项完成并自检后及时提交、推送到仓库保存，再展示本项状态和剩余工作，由用户验证后继续修正。其他获准项可并行，不以用户尚未评审作为开工或提交阻塞。

### 可复用的是规格 不是引擎文件

共享阶段、公式/曲线、参数、坐标、随机规则与测试输入；分别适配 Unity C#/组件/URP Shader 和 Godot GDScript/节点/CanvasItem Shader。`.gd`、`.gdshader`、Godot 场景不能直接导入 Unity；即使都用 C#，引擎 API 与资源配置也不同。

不承诺自动转译、一套文件跨引擎运行、同 seed 自动逐像素相同。可复用明确的纯数学部分，目标是关键动作和视觉语义一致。当前不先建通用导入器或双引擎平台，只按首项真实需求增量组织代码。

## 六 参数与运行输入

每项制作前都要判断“哪些参数值得开放”，并提供直接可播放的命名预设，不交全零占位配置，也不追求旋钮越多越好。以下是轻量约定，不要求先建统一框架；不适用字段可省略并说明。

| 内容 | 要求 |
|---|---|
| 身份 | `effect_id`、`variant`、版本、单次/循环模式 |
| 颜色 | `core` / `body` / `edge` 的有效调色板，不只有换色开关 |
| 尺寸 | 宽度、长度/半径；逻辑像素与世界单位换算、允许范围 |
| 方向 | 默认方向和旋转规则；规格建议 +X 向右、+Y 向上，写明角度单位，Godot 适配画布坐标 |
| 时间 | 预备、主动作、衰减/退出、循环周期与曲线；暂停和慢放行为 |
| 强度 | 本项有效的速度、拖尾长度、粒子上限、分叉/噪声幅度等 |
| 随机 | 仅含随机行为时开放 `seed`；确定性效果不造无效 seed 参数。同一实现和输入可复现，跨引擎需相同算法才谈一致 |
| 运行输入 | 世界位置/速度、朝向、接触点、源/目标 Transform、目标列表、宿主外观/alpha/姿态、触发事件，按需提供 |
| 生命周期 | 重播、停止发射后收尾、立即清除、回收；目标失效和宿主销毁处理 |

### 调参契约

- 区分**可调视觉参数**、**游戏权威输入**、**内部派生值**。预览可模拟运行输入，但不让美术调参悄悄改变伤害、经验、吸附规则或预警时间。
- 每个开放项写明默认值、单位、推荐/有效范围、变化效果、是否整数、是否可为零；非法值有明确拒绝或钳制行为，不能崩溃或无限生成。
- 标明“即时生效”还是“重播生效”。改变种子、发射数量、采样结构等需要重建的项可以重播，不必为了所有参数热更新制造复杂框架。
- 支持恢复默认、重播当前配置；交付当前预设，说明保存/载入方式。恢复默认必须同时清除旧轨迹、旧粒子和旧宿主状态，再按约定重放。
- 测试默认、最小、最大和常用组合，检查尺寸/时长变化不会破坏主体轮廓与干净利落的收束；色彩仍受可读性与亮度约束。

首项挥砍的 `clean_cut` 起始预设：长度 46 逻辑像素、厚度 13 像素、扫角 112°、曲率 0.82，方向朝右，起始 0.025 / 主动作 0.065 / 衰减 0.09 秒，总长 0.18 秒；亮边 `#FFF4CE`、主体 `#F5C56B`、尾部 `#BA7637`。这是该项初始方案，最终值以其配置和 README 为准，不是全库时长/颜色标准或已验收画面。无需随机行为就不暴露 seed；参数须通过实际大小、原速播放再调整。

拖尾消费真实轨迹；经验吸附持续读取目标当前位置，不能把终点烘焙进固定动画。伤害和经验发放由游戏层负责，VFX 不重复决定战斗或奖励结果。

## 七 交付结构

新增效果沿用 `effects/pixel/`，建议按 ID 与英文 `snake_case` 名称建目录。以下是单项制作时采用的结构，不要求本次迁移目录或创建空框架：

```text
effects/pixel/VFX-01_slash/
  src/
    unity/                 # 正式 C#、必要 Shader / Shader Graph
  config/                  # 实际使用的预设，格式按最小需要确定
  assets/                  # 可选静态纹理/网格及其源文件
  preview/
    godot/                 # 按需保留的最小预览适配源，不是 Unity 代码
    preview.gif            # GIF 或真实运行视频，至少一项
  README.md                # 算法、参数、依赖、使用、验证状态
```

预览应用仍在 `preview/godot/`。按 Godot `res://` 项目根规则复制/集成必要文件，说明源与副本的同步关系；预览缓存不是交付源。历史 `source/`、`export/` 空占位可暂留，不再要求往其中生成图集。共享代码结构由首项真实需求确定。

标记“正式可用”必须交付：

1. 实际使用的 Unity C#、Shader 和组件配置。若代码生成对象，给可复现入口；否则附必要 Prefab、材质及依赖。
2. 命名预设、默认值、单位、范围、运行输入与播放/停止示例。
3. 算法/层次、坐标、排序、混合、循环和时间缩放说明。
4. 真实运行 GIF 或视频，注明引擎、版本、子类型、预设与种子；不能用离线合成冒充实时输出。GIF 的调色/透明限制不作为画质唯一依据。
5. Unity 使用步骤与验证记录。Godot 原型和未验证 Unity 代码可先交，但不能标记正式可用。
6. 实际用到的静态素材与适用的 `.blend`、`.pxo` 等可编辑源文件，以及来源/许可证记录。

**不再必交** Sprite Sheet、逐帧 PNG、帧数、图集 FPS 或未使用工具的空工程。截图仅为辅助，不能代替动态预览。禁止 `final2`、`new` 等含糊命名。

## 十 验收清单

### 视觉与时间

- [ ] 以原速、实际游戏像素尺寸检查：主体清楚、方向明确、动作干脆，有限粒子有用途，无装饰堆砌和无意义拖尾。
- [ ] 单次有明确主峰与收束；持续效果内部运动连贯、退出干净；Boss 预警等时长服从玩法，不强行缩短。
- [ ] 像素密度、俯视角、轮廓、色阶统一；深浅背景与叠加正常，无不必要模糊、白边、过曝。
- [ ] 挥砍有扫动、拖尾有历史、雷电连接目标、经验实时吸附；不能只靠缩放、换色或闪烁。
- [ ] 静止/移动/转向/镜头移动与缩放无不受控的抖动、断尾和噪声跳变。
- [ ] 不遮盖危险预警和玩家；预警范围、朝向、时刻与游戏层输入相符。

### 参数与生命周期

- [ ] 颜色、尺寸、方向、时长、种子及专有参数产生预期变化，越界不无限生成对象。
- [ ] 固定种子/输入在同一实现可复现；30 / 60 / 120 FPS 等测试帧率下总时长与主要轨迹在记录容差内一致，不要求逐像素相同。
- [ ] 拖尾、弹道、吸附读取实时输入；宿主外观、alpha、翻转、枢轴与姿态确实生效。
- [ ] 重播、暂停/恢复、慢放、停止、打断、目标失效、回收行为明确；复用无旧轨迹、旧材质残留。
- [ ] 多宿主不串色，状态叠加/清除不损坏原显示；不重复处理伤害和经验发放。

### 性能与 Unity 正式验收

- [ ] 制作时确定粒子/顶点/残影数量、并发数、寿命、可见边界和超限策略；不无限累积。
- [ ] 高频效果按需复用对象和缓冲，避免每帧建材质/大量对象；边界覆盖动作，避免误裁剪。不因此预先搭建庞大框架。
- [ ] 在记录的目标设备、分辨率、Unity/URP 版本与代表性并发场景中测 CPU/GPU、分配和帧耗时；先约定预算，再判断通过，不以“代码所以快”替代测量。
- [ ] Unity 的代码/Shader 编译、2D Renderer 兼容、材质、排序、混合、像素化与运行行为单独验证；Godot 通过不抵消 Unity 未验证。

### 交付与确认

- [ ] 源码、预设、依赖、复现步骤、真实运行预览齐全，不默认依赖图集动画。
- [ ] “Godot 视觉”“Unity 编译”“Unity 运行”“性能”分项写通过、失败、未验证或不适用及原因；未执行不写通过。
